## LawKit

`lawkit/` + `crates/evonomos-law/` form the executable theory and developer-tool layer.

LawKit does **not** encode SOLID, DIP, OCP, ISP, or another design principle as an axiom. It consumes source-observable architecture evidence, demand pairs, lifecycle observations and authority constraints, then emits bounded mechanism pressures, admission states, reversals and abstentions.

Current protocol surfaces:
- v0.1 — pre-outcome moderator inspection;
- v0.2 — post-outcome authority-preserving lifecycle adjudication;
- v0.3 — fresh-world admission under prospectively frozen real-demand and observability gates.

The protocol is canonical; implementation language is not. Current independent semantics use Rust, Python and Node.js because those roles fit the present kernels and verifiers. Future components may use any language that supplies useful independent semantics, static guarantees, solvers, graph analysis, IDE integration or runtime properties.

## GitHub Actions policy

- Actions does not commit experimental results back to this repository;
- raw logs are part of the measurement instrument and obey blindness/firewall rules;
- canonical code/theory changes are researcher-authored, not `github-actions[bot]`.
