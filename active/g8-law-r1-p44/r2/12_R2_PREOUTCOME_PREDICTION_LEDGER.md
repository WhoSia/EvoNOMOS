# R2 pre-outcome predictions and disconfirmation rules

Forecast P1: Each original-backed router preserves the 12 old-client wire projections at stage 0,1,2,3 of the exact frozen order D1,D2,D3.

Forecast P2: After stage k, the first k demanded GET route responses are 200 with the exact predeclared body strings.

Forecast P3: Incremental synthetic route insertion costs [0,1,2,3] on both sides; including P44-R1 normalization, totals for stdlib [0,1,2,3] and Chi [3,4,5,6]. This is a *cost bookkeeping prediction* based on the chosen edit grammar, not measured human time.

Forecast P4 (exploratory): the 3! alternative route-addition orderings also preserve prior goals and the 12 old-client projections at each prefix.

Rival predictions: classical finite reachability / independent route insertions make the same P1–P4 predictions. EAC does not claim incremental explanatory or predictive accuracy here.

Disconfirm P1 if any old request differs, P2 if any response deviates, P3 if app source changes require more or fewer than one declared edit unit under the frozen accounting, P4 if any order fails. Preserve failures and distinguish a model miss from a test harness defect with independently reviewed code.
