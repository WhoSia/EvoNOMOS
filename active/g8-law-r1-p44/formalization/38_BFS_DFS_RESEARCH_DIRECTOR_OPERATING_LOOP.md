## DFS lane: make one narrow conjecture falsifiable

D0 — Freeze exact source grammar, authorized actor edits, protected input-conditioned client observer, cost units, environment/schedule and independent classical competitor.
D1 — Derive the smallest counterexample to the conjectured dependency/contract guarantee.
D2 — Execute original source under real compiler/runtime and independent bounded oracle; record CI failures and source SHA.
D3 — State a conditional lemma with all trust assumptions, proof that would generalize, and reasons it might fail; do not extrapolate from one fixture.
D4 — Decide PASS (for bounded claim), FAIL (counterexample), or UNKNOWN, and commit evidence.

## BFS lane: return to founding question after each deep result

B0 — The founding P44 question is NOT whether a Go fixture compiles, nor whether graph search works. It is:
**Which structural facts of a maintained program make some future changes safely feasible, and can those facts be certified from real source and authentic edit authority at useful cost beyond existing formal techniques?**

B1 — Broaden by equal-information rivals: separation logic/bi-abduction and alias analysis; CEGAR/abstract interpretation; exact model checking/CSP; dynamic schedule explorers; real issue/patch history; online algorithms for future demand timing.
B2 — For each branch ask: what would THIS established method already explain, and what novel falsifiable prediction remains?
B3 — Return to original observability, edit rights, staged preservation, actual developer cost and transport to independent maintained repositories. A model that does not advance one of these is at most a test harness.
B4 — Kill or merge directions producing classical ties; do not multiply F versions simply to advertise progress. Keep strong failed variants as explicit research history.
