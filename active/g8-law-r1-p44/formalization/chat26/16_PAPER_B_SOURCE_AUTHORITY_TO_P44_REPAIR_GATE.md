## 1. Three distinct relations

For a software source version s and an external source record x, distinguish:

- OBS(s,q): HTTP/test/caller observation q generated by the source.
- ASSERTS(x,c): a documented claim c about requested/protected behavior.
- AUTHORIZES(actor,x,c): actor has authority to make c binding for the current patch decision.

A passing test establishes an observed response under an admitted oracle; it does **not** establish that every response is a contractual obligation. An issue comment may specify a desire without the authority of a maintainer agreement. A principle label is an assessment, not a source contract.

Paper B's Section 5 explicitly stipulates the contract: so its four-world Boolean decisions are logically testable but the source authority of B is not empirically observed.

P44 F37's ten HTTP samples establish a bounded current old-client behavior baseline. They do not certify who can change which operation, whether an untested output was promised or which external future demand legitimately binds the application. F38 cannot infer the missing rights merely from equal F37 responses.

## 2. Formal nonidentification witness (classical)

Suppose two candidate source histories h0 and h1 have the same source bytes, complete finite observed HTTP response table and selected route, but their separately authenticated maintainer agreements differ: h0 protects an old optional header, h1 does not. A patch that changes that header is forbidden under h0 and permitted under h1.

Then OBS(h0)=OBS(h1) under the declared test family, yet AUTHORIZED_REPAIR(h0) differs from AUTHORIZED_REPAIR(h1). No classifier receiving only the HTTP response table can be sound and complete for both histories. Additional authority-bearing evidence or abstention is required.

This is a simple information-sufficiency counterexample and follows from classical decision theory; it is *not* a newly discovered universal law.
