# P44 breadth-first review after F16 and during F17

## Original ambition, unchanged

Identify from REAL versioned maintained source, known actor rights and jointly observed client behavior which structures predict safe responses to unknown or later demands. Seek a small, independently checked proof/certificate with actual value relative to full-information classical competitors. Do NOT substitute Go syntax coverage, project version count, GitHub commit count or easy publication topics for this ambition.

## Deep-search lane A — source-derived effect and alias information
F16: real Go heap but alias relation hand-entered into bounded edit graph.
F17: reject all unrecognized typed source syntax and derive exact limited pointer allocation identities. Native runtime comparison is useful but only bounded. If results match ordinary points-to analysis, record classical TIE.
Advance only if the certificate carries verifiable information across independent source revisions or provides a sound modular proof with explicit source dependency boundary.

## Breadth-search lane B — stronger classical alternatives
1. Separation logic/permissions, footprint and local frame conditions: Reynolds 2002, Yang/O'Hearn and O'Hearn/Yang/Reynolds.
2. Bi-abduction for pre/post resource requirements: Calcagno et al. 2009.
3. CEGAR and exact graph/model search: Clarke et al. 2000/2003.
4. Online/reactive synthesis only with genuine first-release-before-future-demand disclosure: Pnueli/Rosner and Borodin/El-Yaniv, latter damaged intake book.
5. White et al. 2009/2012/2014 multi-step CSP/configuration: already a serious classical cost/sequence comparator.

## Breadth-search lane C — external source tasks and real costs
Preseal independent actual maintainer tasks, capture authorized actor and customer baselines before patches, measure proof/certificate construction, repair costs (synthetic and separately measured human labor), negative controls and transport between source revisions. A synthetic unit edit alone cannot prove software maintainability.

## Breadth-search lane D — source semantics / observer scope
Choose a nontrivial client context (e.g. HTTP layered middleware or asynchronous schedule) with *real* repeated traces; establish sound observer coverage or output UNKNOWN. A success on two pointer instances does not imply every old client remains safe.
