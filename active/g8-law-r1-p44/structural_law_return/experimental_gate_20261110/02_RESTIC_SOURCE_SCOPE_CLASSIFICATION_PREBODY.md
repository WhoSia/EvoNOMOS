# Restic 23-Issue External-Demand Cohort — Source Scope and Negative Controls, Pre-Body Protocol

**2026-11-10 KST · committed AFTER title-only 23-result census, BEFORE opening any new individual Restic issue body in this study.** Researcher already has source P35 Restic U/C old results and Restic issue titles, so retrospective contextual information is present. Do not misrepresent as blind prospective outcome forecast.

## Bounded original structural contrast to study
Original P35-P1/P3 has **UNIFIED** one authoritative payload+logical-length record versus **COMPOSED** separately authoritative payload bytes+metadata plus owner-responsibility decoder and coordinator. This was research-owned substitute code tested in compatible original `restic.Backend` interfaces and dedicated bounded original Go package tests, not a deployment replacement of the entire independently maintained Restic app. Result's implementation context is **not interchangeable** with upstream RESTIC repository operational feature set.

## Demand selection independent of result
[Full title-only denominator census](01_RESTIC_ISSUE_TITLE_ONLY_PREBODY_CENSUS.json) contains **23** externally reported Restic issues created from October 10 through November 10, 2026 (GitHub search-query observed; indexing may omit records). **Never silently exclude a bug solely because it seems structurally unrelated or costly to reproduce.** Preserve all 23 in the final descriptive dataset and mark no-eligible-contract tasks explicitly as negative controls.

Pre-body category rules, applied identically to each:
- **DIRECT-POSSIBLE:** title explicitly mentions backend repository I/O, source data stream writes/reads, pack integrity or storage metadata, thereby potentially touching the `Save/Load/Stat/List` abstract interface used in P35. This is a *candidate*, not a claim that existing U/C can fulfill demand.
- **DISTANT:** title concerns backups/excludes/traversal/restore/UI/platform builds/CI that does not obviously require the P35 backend implementation boundary. Count it, but do not invent a U/C-specific patch success or failure.
- **NEW-FEATURE or SUPPORT:** cannot be scored as an existing customer regression without a frozen new requirement/explicit authorization. Credentials/cloud auth backend addition may be DIRECT-POSSIBLE *and* NEW-FEATURE; separate labels.
- **SECURITY/NETWORK:** never implement a new cryptographic/remote-access feature merely to create treatment contrast; annotate scope.

**Pre-body high-recall, title-based triage list for detailed source-eligibility assessment** (not the entire denominator): #22109 S3 backup, #22116 truncated pack rclone backend, #22120 prune timeout, #22133 currently used repo circular backup, #22140 cold storage prune engine, #22150 new cloud backend, #22164 AWS process credentials, #22168 Swift backend CI testing. These titles could involve remote storage/backend behavior; uncertainty retained and full descriptions to be reviewed afterward. Other 15 titles are retained as nominally DISTANT/SUPPORT (not deleted), with category reevaluation from their descriptions as needed.

**Strict followup eligibility** requires all: (1) a frozen correct old-client contract that both P35 U/C arms currently meet, (2) independently stated new behavior implementable in BOTH U/C source programs in the same existing P35 interface layer, (3) actual source file change and full old/new Go oracle, (4) owner edit rights documented, (5) equal source observation and genuine maintainer tool/time budgets. Failure to satisfy these → **INELIGIBLE** for structural source intervention, NOT negative treatment effect. A remote backend feature or restore UI bug in Restic does not automatically become an edit task of our P35 metadata-index toy components.

**Statistical exclusion guard:** 23 query-observed issues from one repo in one month is a small, dependent, nonrandom slice of repository usage; do not compute general software change distributions, p-values or universal architecture optimality. If eligibility is near zero, record **identification/power problem** and widen natural repositories, rather than invent synthetic demands or call negative coverage a law.
