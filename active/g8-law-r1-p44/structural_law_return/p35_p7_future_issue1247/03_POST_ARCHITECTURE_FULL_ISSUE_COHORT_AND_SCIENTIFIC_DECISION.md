## 1. Why collect the denominator?

The preceding [P35-P7 external #1247 replay](01_PRIOR_ARCHITECTURE_FUTURE_EXTERNAL_DEMAND_NATIVE_VERDICT.md) compared authentic **Oct 9** LIVE/SNAPSHOT structural variants on a **Nov 1** independently filed issue. Both arms failed before the same shared `NewPattern` case-normalization fix, and both passed after it: architecture-specific source advantage **not observed**. Merely reporting that hand-chosen later issue while never examining other later issues introduces **demand selection bias**.

This continuation explicitly freezes all public *issue* reports in `go-chi/chi` created from Oct 10 through Nov 10 2026, inclusive, before examining the still-unopened issue #1241 **body**; [pre-body signed census](02_COHORT_CENSUS_BEFORE_NEW_ISSUE_BODY_REVIEW.md), commit `745f600642b3d08207fbd1fb184cf1ff5e60b2a1`, lists both issue titles and numbers. Note: #1247 body and outcome were already known, so this freeze **does NOT undo prior hindsight**. GitHub search can have indexing, permission and date-boundary limitations; use "two observed issues", not a perfect complete population guarantee.

## 3. Scientific outcome is mostly *lack of identifying variation*

- Total observed later issue events = **2**, of which **1** is an existing RouteHeaders behavior regression and **1** a new middleware feature proposal.
- Among **1 eligible native same-demand repair test**, observed difference in number of touched original production source files between LIVE and SNAPSHOT = **0** (both one route_headers.go); both source arms passed the same original full Go/test/vet/race after an identical classical normalization repair.
- This sample **cannot identify** the architecture×demand distribution or an architecture×maintainer effect. The measured result is a bounded **null-control on one issue**, not a statistical "no effect" conclusion. No randomized treatment, no independently acting repairers, no confidence interval, no posterior about real change types.
- Neither task exercises the source divergence (LIVE reads mutable registry at request time; SNAPSHOT freezes at handler creation). Their common semantics or unrelated middleware layer means they are weak probes of that divergence. **Selecting a future issue because it DOES exercise this divergence would bias the estimated natural demand distribution.** Instead include all issues under an author/date/topic-independent selection rule, then stratify by a structural moderator declared from source BEFORE seeing treatment outcomes.

## 4. Updated research target and classical baselines

A fully source-aware static analysis already explains the November case because both architectures share the `NewPattern` parsing/normalization path. A better future classical competitor would include versioned source-impact slices and guarded client contracts; the experiment is not to beat an omniscient exact repair LTS but to compare **design-time selection quality under equal available information**.

The next genuine study needs **multiple matched architecture pairs/independent repositories** (to avoid a two-issue chi-only sample), each fixed BEFORE its later demand stream, an explicit archived cutoff date, an inclusion/eligibility rule that counts negative/null and nonrepair tasks, independent coding actor executions and all attempted/failing patches. Prompts and test oracles must be independently reviewed for correctness. Current 2026 coding-agent evaluation research warns that public benchmark answers can leak and that tests may reject valid solutions: e.g. [OpenAI's February 2026 SWE-bench Verified review](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) and [July 2026 SWE-bench Pro audit](https://openai.com/index/separating-signal-from-noise-coding-evaluations/). These newer published benchmark studies are **external methodological context**, not archive-derived EvoNOMOS results. Do not use a published SWE-bench score alone as architecture evidence.

## 5. Three explicit research decisions

**KEEP**: founding architecture×maintainer×demand estimand, P35 P4 genuine source shared-vs-independent D4/D5 two-stage signs (but cumulative 4-vs-4 file visits), P37 exact-classical ceiling, P40 owner/partial composition semantics, P42 information timing and repair rights, P35-P7 real chronological null-control.

**STOP**: more arbitrary synthetic demand variants, reuse of known #1247 normalization bug as fresh future evidence, source-native CI/test counts as evidence of maintainer labor, new "LAW" names from one extra finite graph.

**NEXT SCIENCE GATE**: recruit/execute at least two independent real coding processes on authentic matched old-correct source architectures, with tool/time and knowledge budgets equal and future tasks issued by nonresearchers after those architectures were fixed. Measure failures, full prior+new client conformance, wall-clock work and inspection activity. Include all eligible issues plus nonrelevant issues in the denominator; not cherry-pick change types with easy contrasts. If no independent agents/tools available, hold rather than pretend patch scripts constitute agents.

**Verdict**: original external post-architecture task stream is mixed, not sufficient for causal law identification; #1247 remains one legitimate null-control. **LAW-R2 HOLD**.
