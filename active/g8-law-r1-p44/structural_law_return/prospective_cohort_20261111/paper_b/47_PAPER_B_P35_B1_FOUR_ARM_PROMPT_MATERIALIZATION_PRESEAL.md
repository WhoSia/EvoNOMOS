## Controls from original P35-B1

The shared task, authorized edit boundary, acceptance tests, original behavior, model/version/temperature, tool privileges, time budget, fresh memory-free context, conditional ordering and task selection must be pinned before sending any arm. The **single permissible difference** between four prompt files is the text under `### Design-advice treatment`. No treatment is privileged to know the answer. Tests, error messages and model failures must remain observed instead of being repaired post hoc.

Treatment conditions:
- `NONE`: neutral, no extra design principle directive.
- `HARD_SOLID`: hard design principle compliance (experimental intervention, not the project's recommendation).
- `SCOPED_SOLID`: use design principles only where context supports them.
- `EVIDENCE_CONDITIONAL`: evidence and authorized requirements determine suitability, with explicit uncertainty.
  
Original rivals:
- lexical echo: output prose differs, actual code does not.
- source-oracle dominance: all arms meet same tests and API obligations.
- helpful hard guidance: strong doctrine improves correctness or code quality in some worlds.
- model/context differences: if task or tool rights differ, do not attribute result to one paragraph.

**Important safety/epistemic note:** the HARD_SOLID text is a controlled scientific intervention and not authoritative engineering advice. This experiment can at most identify current prompt-level effects on tested agent executions; it cannot inspect training corpora, historical normative shifts or model-weight representations.
