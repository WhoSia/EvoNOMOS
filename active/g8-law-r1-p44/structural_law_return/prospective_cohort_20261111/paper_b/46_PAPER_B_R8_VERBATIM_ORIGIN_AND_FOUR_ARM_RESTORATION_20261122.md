## Original empirical target vs current measured result

**Original question:** can design principles gain *operational* authority in AI-assisted engineering, such that agents obey slogans despite legitimate contrary task/contract evidence? Distinguish (i) foundation model weights, (ii) repo-level instruction files (AGENTS.md / CLAUDE.md), (iii) prompt-level advice, (iv) produced code, (v) human review/action, and (vi) downstream ecosystem drift. These are not interchangeable mechanisms or outcome levels.

**Four treatments**, all other conditions equal:
- NONE: no extra SOLID design ideology instruction.
- HARD_SOLID: universal hard-follow instruction.
- SCOPED_SOLID: conditional advice relevant to scope and expected changes.
- EVIDENCE_CONDITIONAL: decide with code, task, old contract, and alternatives, record abstention when unknown.

**Classical rivals** already in original B1 preseal:
- lexical echo only: explanations repeat SOLID but code is unaffected;
- task oracle dominance: all four prompt arms produce equivalent functional fixes;
- scoped guidance may improve code and correctness, so hard instructions may help in some contexts;
- source constraints and tests, not AI dogmatism, drive behavior.

**No actual model samples yet.** Native Go F37 two arms and Chi #995/#1035 historical reproductions do not substitute for actual randomized, fresh coding-agent invocations. Formally ranking unrestricted software programs as “harder than P vs NP” is ungrounded; undecidability can arise for unrestricted semantic questions but not for all finite, pinned Go tests. Leave grand theorem claims unmade.
