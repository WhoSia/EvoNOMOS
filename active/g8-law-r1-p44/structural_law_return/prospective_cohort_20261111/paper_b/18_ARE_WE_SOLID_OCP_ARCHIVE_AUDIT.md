# Paper B — What the Archived OCP Labels Measure

The [Drive archive](https://drive.google.com/file/d/12LDcKFBpJRkwH-zYJZ6Uhk9pE3RzgnUe/view) was matched to the ASE 2025 replication package by its internal README and dataset structure. The [custody receipt](./17_SIMULA_IBIS_INTAKE_RECEIPT.md) carries the exact SHA-256. No archive script, serialized bytecode, sample program, or Git hook was run. The inspection reads the five JSON ground-truth documents and counts archived completion rows. Run `python3 audit_are_we_solid.py /path/to/AreWeSOLID.zip` to regenerate the [inventory](./are_we_solid_inventory.json). Python 3.12 reproduced the same JSON from both copies bracketing the Drive move.

The archive contains 48 labeled examples for each of five principles, with four examples per language × difficulty cell. The C-sharp label is `C#` in DIP and LSP and `CSHARP` in the other three; the audit normalizes this token when checking cell counts. OCP has 48 input/output pairs, and 16 stored completion files with 48 rows each. Each OCP ground-truth row has exactly `input`, `output`, `language`, `level`, and `violation`. A separate repository file can carry context that the row schema lacks. The package scenarios and paper should be consulted when interpreting individual labels. [Paper](https://arxiv.org/abs/2509.03093)

For the twelve Python OCP pairs, top-level class bodies were compared by the names of non-underscore methods declared in each snippet. Nine outputs omit at least one input declaration. In one-based OCP row 37 the omitted names include `Rectangle.get_width`, `Rectangle.get_height`, `Circle.get_radius`, and `Shape.get_type`. The refactoring puts area calculation behind a shape method. It preserves the displayed area calculation design target while removing the explicitly declared getter surface. A caller written to call `Rectangle.get_width()` would exercise a different compatibility question from a caller that only uses `AreaCalculator.calculate_area()`. The audit counts declaration removal, which on its own leaves inherited methods, intended API scope, semantic behavior, and real client use unestablished.

The 2025 benchmark evaluates agreement with its supplied violation label. A subsequent OCP evaluation can introduce a separately stated change demand and a pinned old caller contract, then test whether a patch extends the program and preserves the required observations. These are three inspectable criteria beyond the original row label. This audit supplies a concrete motivation for doing that and makes no claim about the reported classification scores.

## What reached the recorded judge prompt

All 768 saved OCP completion rows contain an explicit prompt string and its submitted code string. In every record the code occurs exactly once inside the prompt. Replacing that occurrence yields 24 distinct scaffolds across four strategies: default 4, ensemble 8, example 8, smell 4. Inspection of the scaffolds shows generic classification and formatting instructions, sometimes with a principle-level cue, without a separate item-specific change request or protected caller contract. The EXAMPLE cue requests polymorphism in appropriate branch-heavy logic but leaves what must change and which existing caller must survive to inference from the snippet. This is evidence about archived prompt text. It leaves the full provider request envelope, what could be inferred from the particular snippet, and maintenance performance open.
