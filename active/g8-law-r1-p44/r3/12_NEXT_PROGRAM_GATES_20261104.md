# Next scientific unit: R4 source-certificate feasibility under equal classical budgets

Do not use "R3 succeeded" as justification to promote LAW-R2. R4 is an experimental proposal, not executed.

### RQ1 — soundness/coverage
Can a source-visible certificate (ownership / effect / old-client observer / guarded safe edit step) make nonvacuous predictions for real maintainer-created changes while tracking false negatives and incomplete source behavior? Define source scope, missing calls, reflection, dynamic routing, concurrency, and no guessed proof of completeness.

### RQ2 — equal-information competitor
Build two checkers on identical pinned source snapshot and identical customer/test oracles: (A) EAC proposed compressed certificate, (B) compositional separation-logic/alias+effects + source-aware bounded repair search, plus a strong conventional exact finite edit search. Compare accuracy, soundness counterexamples, certificate bytes, time/CPU and code intervention cost. The full exact oracle cannot be surpassed on correctness within its complete finite domain.

### RQ3 — externally selected maintenance cohort
Freeze selection rule *before* reading future outcome patches. Select repository/version/task from actual independently maintained issue/PR history; isolate the 'before' source and issue report from the subsequent fix. Note that already public patches are available and thus only auditor-blinded/temporal emulation, not genuinely unseen predictions. Compare across projects, split training/heldout by repository and time, and identify developer familiarity confounds.

### RQ4 — customer observer completeness
Use regression tests and carefully scoped metamorphic/concurrency observer expansion. Failures need counterexample shrink and explicit observation-language growth rather than post-hoc selective retuning. For concurrent modules, compare against systematic schedule exploration or DPOR.

### RQ5 — measurable maintenance
Do not substitute lines changed, synthetic edit units or PR wall-clock lead time for individual effort. If actual effort cannot be collected reliably, use vector metrics (files, tested contexts, patch validation workload, reviewer involvement) and label unobserved human time as missing.

### Three stop criteria
1. Every demonstrated advantage is explained by equal-information classical counterpart -> report classical TIE.
2. Results require cherry-picked task families, asymmetric rights or postselected observer -> stop broad claims.
3. EAC cannot scale to meaningful heldout source or produces only unverifiable static AST facts -> demote to methods/framework note rather than scientific law.
