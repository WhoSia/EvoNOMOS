## Why F20 does not answer the founding question

F20 used three genuine public source projects and native original Go parent/post code, but all chosen commits and their defect description/changed filenames were visible to the researcher before custom tests were authored. Successful retrospective `before!=after` witnesses are neither predictions made before unknown future demands nor evidence of EAC novelty. ## Candidate genuinely informative next design

1. Have an independently delegated task selector or genuinely new issue stream define the later demand after source observation/prediction receipt is immutably committed. If independent selector is unavailable, use strict chronological simulated holdout, label it BACKTEST, not live prospective.
2. Pin full pre-demand repository tree SHA, module graph and checksums, license, build tags, compiler version, source ownership/actor rights and named old-client contexts. No partial Go test stands in for universal old-client safety.
3. Declare the exact future repair family predictor before seeing demand: eligible source regions, dependency/callback/alias structure, predicted safe edit feasibility or abstention, estimated required source-edit family, proof/cert size, and cost units. Never replace with knowledge of the eventual patch.
4. Rivals get identical source/rights and time budget: full Go source-aware call/dependency analysis, existing test coverage plus deliberately targeted regression tests, source graph/model checking where feasible, ordinary cached dependency graph, bi-abductive ownership/footprint reasoning, and feature/configuration methods when comparable.
5. Score genuinely pre-specified outcomes: false-safe rate, unknowns/abstention, witnessed old-client regressions, selected repair-family prediction accuracy, all-in CPU/memory and human labor separately, release cost vs optional synthetic edit count. Commit negative predictions and exclusions, not only wins.
6. Study *nonanticipation* only when the receipt reliably predates later issue disclosure; an archived 2024 GitHub issue is public and cannot become truly novel future information just because a researcher looks at it late.
7. Precommit stopping rule: no strong law or publication claim for source-limited examples or conventional cache/program-test ties; independently replicable advantages must survive matched-information classical competitors.
