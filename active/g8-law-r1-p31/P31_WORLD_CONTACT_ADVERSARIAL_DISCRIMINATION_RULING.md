## II. Three explicit competing explanations

- **B0 / Topology-only baseline:** counts of coupling/dependency fanout, independently duplicated conversion sites, interface methods, modified files predict all available observations. All present results are plausibly explained by B0.
- **B1 / Demand × structure fit:** change propagation depends on which clients require the *same semantic variation* and which are constrained to obey distinct behaviors. Shared mapping helps only on jointly required change; display-only features should not be injected into ingest; unrelated demands can be neutral. This is a plausible refinement of information hiding and co-change research, **not an original law**.
- **B2 / Capability-obligation alignment:** a client that only needs static metadata should not need execution capability. Interface splitting reduces mandatory implementation methods but can add registry/adapter overhead. This is standard ISP-style territory and currently **B0's method count already suffices** for the observed 6→1 obligation difference.
- **H / Candidate higher-order structural mechanism (not admitted):** the placement of change authority relative to the *actual obligation graph* could predict a lifecycle vector that B0 cannot. To be genuinely additional, H must make a different pre-outcome prediction from both B0 and B1/B2 on a **real, source-grounded, functionally complete** held-out change.

Do not invent a new quantity as if naming it established novelty. H currently has **zero demonstrated incremental predictive effect**.
