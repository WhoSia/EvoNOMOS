## Post-source paired benchmark extension (separate secondary court)

Before any Gorilla native outcome was available, two source variants were already authored and an unpaired GitHub matrix was queued. Because GitHub matrix arms can execute on **different runners**, a plain cross-arm performance comparison would be vulnerable to CPU/host noise. A **separately labeled, post-source protocol extension** was committed [#228e2cc](https://github.com/WhoSia/EvoNOMOS/commit/228e2cc3c837a0a397321db6364fe1f57ed02415) as [same-runner benchmark workflow](../../.github/workflows/g8-p36-o2-paired-gorilla.yml). Each job checks out exact identical Gorilla revision in two independent directories and benchmarks both EAGER and LAZY **on the same runner**, with experiment order EAGER→LAZY and LAZY→EAGER on two runs, using common Go test and 5 repeated `-benchtime=250ms -cpu=1 -benchmem` estimates. This improves source-runner comparability, but is **not** prospective relative to knowing source implementation designs. It leaves earlier frozen acceptance and the H-transport-sign prediction unchanged; is NOT a redefined original primary protocol, and still lacks full statistical independence and robust matched production workloads. A successful repeated sign within both orders would provide stronger bounded support, not causality or new law. At this document update both initial Gorilla and this paired validation had no completed CI evidence.
