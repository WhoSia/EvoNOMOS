## Precise P36 mathematics: repair survival is not a scalar

Given original software source A, fixed admissible source-edit grammar Γ, demand d, functional contract Q and allowed executor/environment c, define:
```
R_d^{Γ,Q,c}(A) = { B : B is reachable by Γ-edit from A and B satisfies all Q-prefix tests under c and d }.
```
For an existing repaired B and **fresh** future demand e, let
```
Surv_0(B,e) := B satisfies the full new demand e without any source rewrite.
Surv_Γ(B,e) := exists C in R_e^{Γ,Q,c}(B).
Guaranteed_Γ(A,d,e) := R_d^{Γ,Q,c}(A) nonempty
                       and every B in R_d^{Γ,Q,c}(A) satisfies Surv_Γ(B,e).
```
`Surv_0` is zero-edit future behavior, **not** `Surv_Γ` under new repair. A found retained witness proves `May(Surv_0)`; a found erased witness refutes `Must(Surv_0)` under exactly the fixed observed candidate family Γ. Neither one determines a general architecture policy.

A separate **epistemic bound**: if Γ restricts future repair to a deterministic transformation of *current retained runtime state* with no external logs, and two pre-deletion histories have different required restore outputs but the same post-deletion state, then no Γ future transform can recover the correct answer for both histories. This is standard indistinguishable-state/information loss reasoning. Crucial premises: no source of the discarded data; same post-deletion state; exact restore requirement; no later input supplying the missing closure. A program with persistence/replay/authorized log is **not** covered.

## Prospective P36-O3 bridge, not a new theorem

Take proven original Chi Go router source, and freeze a new matched functionality: an existing first registered rule can be disabled while preserving the remaining observable routing and concurrency contract (D14); later future requirement D15 asks to reenable the *same* prior middleware and original priority. Two intentionally different authorized D14 source repairs:
- `RETAIN`: preserve disabled route metadata and middleware for future recovery; current routing sees it removed.
- `ERASE`: discard deleted route metadata and middleware under current-state-only grammar; current routing sees it removed.

At D14 all observable behavior should be identical under the frozen tests. Under D15:
- `RETAIN` might satisfy `Surv_Γ` with local enable operation.
- `ERASE` cannot recover a truly lost closure from current state alone across two observationally identical deletion histories unless permitted repair context is expanded (external event log/re-registration identity/etc.).

The goal is to **test source-level information retention as a moderator of option survival**, not claim that memory retention is a new principle. Standard information hiding / program-repair overfitting / cache and classical observability theories are undefeated. Primary APR risk: a patch passing a finite test suite may fail independent future tests (e.g. Qi et al., ISSTA 2015; follow-up automated patch assessment studies). No claim of extrapolation to every arbitrary Γ.
