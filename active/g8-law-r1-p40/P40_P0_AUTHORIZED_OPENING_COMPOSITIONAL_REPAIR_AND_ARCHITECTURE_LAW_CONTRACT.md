## 2. P40 first actual theoretical hypothesis

**Two dimensions must be separated:**

A. **Extensional endpoint compatibility**: old clients still work and the desired future capability is present after all edits.

B. **Intensional safe edit reachability**: there is a finite sequence of *authorized, individually accepted source modifications* in which EVERY intermediate source still satisfies the explicitly declared old-client contracts, Go type checking and relevant owner permissions.

An endpoint can be valid without a safe single-edit path. A global cyclic-order gluing claim can hold for mathematical rights signatures and fail for actual source-level compatibility if a shared boundary invariant forbids the necessary intermediate edit.

The concrete discriminating world is **Go method-set interface evolution**. Compare:

- **Coupled contract expansion**: adding new capability to the EXISTING interface that old implementers must continue to satisfy.
- **Segregated capability extension**: keep the old interface fixed, define a NEW embedded extension interface, and upgrade only the authorized implementation.

Use one protected old implementation (`Legacy`), one changeable provider (`Fast`), an unchanged old client consuming each as `Port`, and new optional future demand `Next()` for `Fast`. Source edit operations are precisely: T = publish new interface contract, M = add `Fast.Next`; `Legacy` and old client text must not change. All source revisions and BOTH edit orders must be independently Go-compiled. Treat owner permissions as explicit **scenario assumptions**, not empirical maintainer approvals.

**Conditional hypothesis:** in this world, coupled changes to the existing Port contract have NO legal source repair path to the exact future demand because protected `Legacy` no longer implements Port. Segregated extension can satisfy the old contract and the new Fast capability, with both T/M orderings type-valid, creating two internally disjoint one-step paths in its two-edit edit cube. This is a real source-typing consequence but a **classical interface segregation / Go method-set entailment** until a stronger architectural law or a prospectively distinct classical rival is defeated.
