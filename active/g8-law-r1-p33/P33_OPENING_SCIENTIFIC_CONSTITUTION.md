## New explanandum
For a frozen real OO design a, a prospectively specified requirement d, environment/configuration c, permitted source-edit language L and **complete** behavioral acceptance oracle O(d,c), discover the minimal *family of admissible repairs* and its source-grounded structure. Seek prior-outcome-independent conditions under which ownership/contract structure changes the Pareto frontier or admissible policy ordering. Do not simply rename the traditional change-impact set.

```text
Admissible(a,d,c) = { b | b reachable by permitted implementation; O(d,c,b)=PASS }
Support(a,b) = actual source locations materially modified in b
Repairs(a,d,c) = inclusion-minimal supports among Admissible(a,d,c)
RealizationPolicy pi: requirement/history/context -> one admissible implementation
V_pi(a,d,c) = observed (S,L,C,A,Q) scoped to an explicit execution oracle
```

For a Turing-complete language and broad unrestricted changes, these sets are not generally mechanically enumerable or provably complete. All finite search claims must state candidate grammar, oracle scope and whether completeness holds *only within that grammar*. A feasible repair may require new files, shared code, and coordination; equal support does not entail equal source semantics.

**Important counter-boundary:** Antichain pruning preserves optimum only for monotone costs on repair supports (e.g. fixed nonnegative additive edit-site weights). It does NOT automatically preserve a Pareto frontier over S/L/C/A/Q, long-run cost, future demands, or behavior when supersets enable cheaper future maintenance. Q is an admissibility gate, not a scalar weight.
