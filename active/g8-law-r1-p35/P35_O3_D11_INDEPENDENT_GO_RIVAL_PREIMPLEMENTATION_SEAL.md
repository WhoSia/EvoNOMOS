## D11 shared contract — specific to synthetic `X-EvoNOMOS-Mode` header, not HTTP in general

For explicitly declared experiment route/header matchers on `X-EvoNOMOS-Mode`, treat each physical field as a list in RFC-style CSV *token syntax only* (not claim of HTTP/RFC header standards): unquoted tokens split at commas; a fully double-quoted token may include literal commas; doubled quotes `""` inside a quoted token represent a literal `"`; trim surrounding spaces; ignore empty unquoted tokens. Tokens are case-insensitive for Chi (its frozen prior behavior); Gorilla original matcher remains case-sensitive unless the experiment freezes equivalent-case inputs, so shared cross-library oracle uses lower-case only. A malformed quoted field must yield **no matching tokens from that physical field**. Other physical fields still count. Existing D9/D10 correct unquoted and repeated headers remain equivalent. Distinct header keys and RouteAny are Chi-specific and NOT cross-repo rank variables. Regex matching for Gorilla must apply to each *decoded token* rather than raw field, maintaining original regex semantics on old noncomma cases. This D11 is a **specific new experimental feature demand**, not an assertion that all HTTP field values may legally be parsed as CSV.
