# P35-B1 — Prospective Go Coding-Agent SOLID-Instruction Experiment: Design Only

**2026-10-09. PRE-AGENT-RUN. Zero agent assignments, model generations or evaluated agent repairs are reported here.** Paper B stays a research hypothesis, not a submitted manuscript. No inference about proprietary model pretraining is permitted.

## Competing explanatory hypotheses

- **P (instruction effect):** `HARD_SOLID` produces more declarative principle-conforming architectural choices than `NONE` in the tested coding agents. This may improve, harm, or not affect correctness.
- **C (conditional guidance):** `SCOPED_SOLID` and `EVIDENCE_CONDITIONAL` may preserve more original Go behavior under a maintenance demand than the unconditional condition; direction is **not fixed** before task/source eligibility.
- **N (lexical echo rival):** principle-heavy prompts mainly change written explanations, not code/test behavior; test via source AST/functional outputs separately from prose.
- **K (task constraints rival):** task-specific source and frozen tests dominate all conditions, producing no measurable behavioral separation. A null is a finding, not infrastructure failure.

**All are hypotheses**, not facts about agents or historical SOLID reception. Martin (2000), Black (2013), Gloaguen et al. (2026), and Esposito et al. (2026) original PDFs are in user-controlled canonical Drive 10_PAPERS; their claims must not be paraphrased into a causal proof of train-time SOLID dogmatization. The Kay 1993 scanned file remains limited for detailed quotation.

## Correct experimental unit and intervention

Each **fresh agent invocation** is a single unit, with cloned exactly pinned Go repository and same complete functional task description; do not reuse agent conversation context across conditions. Four mutually exclusive condition files `NONE`, `HARD_SOLID`, `SCOPED_SOLID`, `EVIDENCE_CONDITIONAL` differ **only by the design-advice paragraph**. Every file shares immutable task, actual source SHA, budget/tool access, language/toolchain, and nonnegotiable contract/testing requirements. Do not silently add privileged hints about where the desired repair should occur in only one arm.

Create a predetermined Latin-square / balanced condition ordering and fixed assignment seeds BEFORE model execution; block by **task and model** rather than declaring every repeated run independent. If stochastic seeds unsupported, record that and use separate fresh contexts with documented order. Contamination rule: neither benchmark source has a solved D11 patch in the read-only task branch visible to agents; the evaluator keeps the D11 acceptance suite private until execution, while the task contract itself is identical and fully specified for all treatments. Freeze a common time/token budget and disallow surprise external tool privileges. No agent model/temperature availability is assumed.

## Scoring contract (NOT a single economic index)

**Primary:** native Go full-module tests, original regression/race and hidden prospective oracle (binary and per-case vector), with same CI environment in all conditions. **Secondary separate axes:** API preservation, source AST edits, number and kinds of helper abstractions, source-structure rationale, stated applicability/exceptions, response to a follow-up negative counterexample, and `ABSTAIN` when no valid patch found. `Written use of SOLID vocabulary` is NOT correctness. Tool errors, early context limits and no generated patch remain observed failures/holds, not replaced with manual solutions.

**One invalid conclusion to block:** even if `HARD_SOLID` changes a Go agent’s output in a controlled prompt experiment, that does NOT demonstrate historical pretraining-corpus cause, model-weight axioms or long-run professional canon formation. Historiography and instruction-response experiments estimate different targets.

## Go tasks and replication eligibility

- Candidate T1: pinned Chi D11 quoted-token upgrade, original Go source, task oracle neutral to architecture and helper choice; source variants cannot expose previously completed D11 patches to agents.
- Candidate T2: genuinely separate Gorilla Mux v1.8.1 header matcher D11 subset, if its source/API and common task Q pass independent eligibility; this is a cross-codebase task, not a paired same-implementation comparison.
- A second task with **a context where information hiding beats naive helper proliferation** is required to avoid prompt favoring an a priori code style; it must be frozen before the agent wave and should include a valid alternative that looks noncanonical under hard SOLID. No forced claims if it cannot be found.
